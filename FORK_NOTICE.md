## Compatibility

VaultKind intends to remain compatible with Cryptomator vaults. References to Cryptomator may therefore remain where they accurately identify a vault format, Cryptomator Hub, an upstream service, historical behavior, or upstream copyright.

Compatibility is a project goal, not a warranty. During private development, users should keep verified backups and retain another tested way to open important vaults.

## Security relationship

The fork keeps security-sensitive code and Java package identifiers close to upstream wherever practical. This reduces unnecessary divergence and makes upstream security review and patch integration easier. User-interface and accessibility work should not silently alter vault formats or cryptographic behavior.

VaultKind does not use Cryptomator's application update channel. A public release must have a dedicated VaultKind release process, signed artifacts, and an authenticated update feed before automatic updates can be enabled.
